# IIT Faculty Search

A faculty discovery system for Illinois Institute of Technology. Search across all departments by name, research area, publications, and more — using keyword (BM25s), semantic (Qdrant + sentence-transformers), and hybrid (RRF) search.

## Project Structure

```
iit-faculty-search/
├── scraper/
│   └── scraper.py          # Scrapes IIT directory → faculty.json
├── build_indices.py        # Builds BM25s, Tantivy, and Qdrant indices
├── backend/
│   ├── main.py             # FastAPI app
│   ├── search.py           # Search logic
│   └── requirements.txt
├── frontend/
│   ├── index.html
│   ├── script.js
│   └── style.css
├── indices/                # Generated by build_indices.py (gitignored)
│   ├── bm25s.pkl
│   ├── tantivy/
│   └── qdrant/
└── faculty.json            # Generated by scraper (gitignored)
```

## Setup

### 1. Install dependencies

```bash
pip install bm25s qdrant-client sentence-transformers fastapi uvicorn
```

Tantivy is optional (adds field-boosted structured search):
```bash
pip install tantivy
```

### 2. Scrape faculty data

```bash
python scraper/scraper.py
```

Outputs `faculty.json` in the repo root. Scrapes ~700–800 faculty profiles from `iit.edu/directory` with a 0.4s politeness delay — expect 10–15 minutes for a full run.

### 3. Build indices

```bash
python build_indices.py
```

Builds three indices under `indices/`:
- **BM25s** — keyword retrieval index
- **Tantivy** — field-boosted structured index (skipped gracefully if not installed)
- **Qdrant** — local persistent vector store using `all-MiniLM-L6-v2` embeddings

This runs once. Re-run only if `faculty.json` is regenerated.

### 4. Start the API server

```bash
uv run uvicorn backend.main:app --reload --reload-dir backend --port 8000
```

API at `http://localhost:8000`. Interactive docs at `/docs`.

### 5. Open the frontend

Open `frontend/index.html` in your browser and connect to `http://localhost:8000`.

Or serve it locally:
```bash
python -m http.server 3000 --directory frontend
# open http://localhost:3000
```

## API Reference

### `GET /search`

| Parameter | Type | Description |
|-----------|------|-------------|
| `q` | string | Search query |
| `dept` | string | Filter by department name |
| `mode` | string | `hybrid` (default), `keyword`, `semantic`, `structured` |
| `limit` | int | Results per page (default 10, max 50) |

**Example:**
```
GET /search?q=machine+learning&dept=Computer+Science&mode=hybrid
```

### `GET /search/keyword?q=...&limit=10`
### `GET /search/semantic?q=...&dept=...&limit=10`
### `GET /search/structured?q=...&name=...&dept=...&limit=10`

### `GET /departments`
Returns sorted list of all unique department strings.

### `GET /faculty/{slug}`
Returns full record for a faculty member by profile slug (e.g. `jane-smith`).

---

## Search Modes

| Mode | How it works |
|------|-------------|
| **Keyword** | BM25s full-text search across name, titles, departments, research interests, publications |
| **Semantic** | Qdrant vector search using `all-MiniLM-L6-v2` embeddings; supports department filter |
| **Structured** | Tantivy with field boosting: name×5, departments×3, research×2, titles×1; falls back to BM25s |
| **Hybrid** | Reciprocal Rank Fusion (k=60) over all three search legs, run concurrently |

## Production Deployment

The backend auto-switches between local Qdrant and Qdrant Cloud based on environment variables:

```bash
export QDRANT_URL=https://your-cluster.qdrant.io
export QDRANT_API_KEY=your-api-key
```

Without these, it uses the local `indices/qdrant/` directory.

The frontend's `API_URL` variable in `script.js` (line 2) can be updated to point to the deployed backend URL.

## Notes

- Profile pages vary in structure across departments — some fields may be missing for certain faculty.
- Embeddings are generated once at index time; only the query is embedded at runtime.
- The scraper uses `requests` + `BeautifulSoup` with a 0.4s delay between profile requests.
